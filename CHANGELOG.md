# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `GS_REPO_PATH` environment variable is now exported to every tmux window created for a session, set to the session's worktree folder. Configured window `command` entries (and any interactive shell in the session) can reference it, e.g. `$GS_REPO_PATH`. It is injected via tmux's `-e` flag on `new-session`/`new-window` and also set at the session level (`set-environment`) so later-created panes inherit it. Requires tmux >= 3.0 (for the `-e` flag).
- Configurable default branch prefixes for newly added repositories. The add-repo flow (TUI wizard and the CLI `--prefix` default) now proposes the standard list `feature, bugfix, chore, refactor, docs, test` instead of just `feature`. The list is read from a new `default_branch_prefixes` key in the global `~/.config/git-session/config.toml`, which the first-run wizard seeds as an editable template; when the key is absent git-session falls back to the standard list. The key accepts either a TOML array (`["feature", "bugfix"]`) or a quoted comma-separated string (`"feature,bugfix"`) for convenience. The `git-session config` output now also displays the configured default prefixes. See `README.md` and `docs/configuration.md` for details.
- Automatic recovery of accidentally-deleted bare repositories. If the bare repository (`<root>/<repo>/<bare>.git`), the repo folder, or even the entire root folder is removed from disk, git-session re-creates the missing directories and re-clones from the origin URL the next time the repository is opened. Recovery is gated on the centralized per-repo config being present (it is the only durable place to record the recovery metadata). Repositories added via the wizard now record `origin_url` and `root` in their centralized config; existing repositories are silently backfilled the first time they are opened after the upgrade. See `docs/configuration.md` for details.
- Vanished repositories — those whose on-disk folder has been deleted but whose centralized config still exists — now appear in the main repository list so that recovery can be triggered through the normal CLI/TUI flows. A vanished repo is only listed under a configured root when its central config explicitly records that root (no fallback): this prevents the `config remove-root` cascade from misattributing repos belonging to other roots and accidentally deleting their central configs. Vanished repos with a missing or non-matching central `root` are skipped with a one-line warning in general listing flows (main menu, `--repository <name>` lookup) so the user is aware they exist; the warning is suppressed in the `config remove-root` cascade where it would be off-topic noise. Repos remain reachable via `--repository <name>` regardless.
- Centralized per-repository configuration at `~/.config/git-session/repos/<repo-name>.toml`. When both the centralized and per-repository (`.git-session.toml`) files exist, the centralized file takes priority. This makes it possible to track all session configurations in a dotfiles repository and share them across machines.
- `create`, `remove`, and `fix` subcommands for fully non-interactive session management
- TUI pre-selection: partial CLI flags open the TUI at the step where input is still needed
- `config remove-root` now accepts an optional positional `<path>` argument
- CLI documentation at `docs/command-line.md`
- Remove-repository UX: in the TUI, press `D` (capital) on a highlighted repository in the main menu to remove it. The confirmation screen lists the repository name, on-disk location, and number of sessions that will be deleted. The operation kills every associated tmux session, deletes the repository directory (bare repo + all worktrees), and removes the centralized config file at `~/.config/git-session/repos/<name>.toml`.
- `git-session remove-repo <name>` CLI subcommand for the same operation. Shows a summary and requires the user to type `yes` to confirm; pass `--yes`/`-y` to skip the prompt.
- `git-session add-repo <url>` CLI subcommand to clone and register a new repository. Mirrors the TUI add-repository wizard: produces the same on-disk layout (`<root>/<name>/<name>.git`) and writes the generated TOML to `~/.config/git-session/repos/<name>.toml`. Accepts `--root`, `--name`, `--branch`, `--prefix` (comma-separated list), and `--yes`/`-y`. When `--root` is omitted, a numbered picker is shown with the first configured root as the default; when `--root` points to a path not yet in the configuration, the user is asked whether to register it on the spot. `--yes` skips both prompts (uses the first root, or silently registers the new path).

### Fixed

- New session worktrees are now based on origin's branch state instead of the local base branch. Previously the pre-creation fetch used a non-forced `<branch>:<branch>` refspec that updates the local branch directly; it silently fails (warning only) when the local branch has diverged from origin or is checked out in another worktree, after which every new worktree was created from the stale local branch. The fetch now updates the remote-tracking ref `refs/remotes/origin/<branch>` with a forced refspec, and the worktree is created from that ref, so new sessions always start from the latest origin state. When the remote-tracking ref is unavailable (e.g. no reachable origin), the local branch is used as a fallback and the fetch warning now mentions that the worktree may be based on a stale ref.
- TOML array parsing (`parseTomlArray`, used for `roots` and `default_branch_prefixes`, plus the standard-prefix seeding) no longer leaks memory on allocation failure: a duplicated element is now freed if the subsequent list append fails, and partially-built lists are released via `errdefer`. Reading the global config also frees the prior list when a key is duplicated in a hand-edited `config.toml` (last occurrence wins).
- Long session names no longer disappear from the Remove/Fix session lists in the TUI. A session whose name was long enough to exceed the list's content width caused the label to soft-wrap onto a second line; because the list draw loop advances by exactly one row per item, the wrapped line was overdrawn by the following entry, rendering the long session as a blank or missing row. Labels are now truncated with a trailing ellipsis (on UTF-8 codepoint boundaries) so every entry stays on a single line and remains selectable.

### Changed

- Migrated to Zig 0.16.0. The codebase now uses the new `std.Io` interface introduced in 0.16: all filesystem, process-spawning, and environment lookups flow through an explicit `io: std.Io` parameter (plus an `env: *std.process.Environ.Map` where environment variables are read), and `main` receives its allocator, Io implementation, and environment map from the new `std.process.Init` entry point. The libvaxis dependency was updated to v0.6.0 (the first 0.16-compatible release), the internal `src/io.zig` helper module was renamed to `src/term.zig`, and building now requires Zig 0.16+ (`minimum_zig_version` is enforced via `build.zig.zon`). No user-facing behaviour changes.
- Move usage cache file from `~/.config/git-session/` to `~/.cache/git-session/` (respects `$XDG_CACHE_HOME`) to keep the config directory clean for dotfile managers
- Add-repository wizard now writes the generated TOML to the centralized location (`~/.config/git-session/repos/<repo-name>.toml`) instead of into the cloned repository. The per-repository `.git-session.toml` file is still read as a fallback when no centralized config exists.
- Improve the "unknown argument" error in the top-level CLI dispatch: arguments starting with `-` are now reported as `Unknown flag: ...`, and when stripping the dashes yields a known subcommand (e.g. `--remove-repo` -> `remove-repo`), a hint clarifies that subcommands are positional rather than flags.
- `config remove-root` now lists the registered repositories (if any) under the targeted root and offers to remove them along with their tmux sessions before unhooking the root. The default is no-delete (only the root is unhooked from the configuration); pass `--yes`/`-y` to cascade the full repository teardown non-interactively. After the cascade, the root folder itself is `rmdir`-ed when empty (loose files or unrelated subdirectories cause the folder to be kept with an explanatory note instead). Centralized per-repo configs (`~/.config/git-session/repos/<name>.toml`) for repos under the removed root are always cleaned up — even when the user declines the on-disk deletion — because they would otherwise become orphaned and unreachable.
- Replaced the internal example repository name used in the `tmuxSessionName` documentation and tests with a generic placeholder. No behaviour change.
